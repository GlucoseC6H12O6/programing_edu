## P12. 함수, 매개변수, 반환값

### 이번 레슨이 끝나면

함수를 정의하고 호출할 수 있다. 인수와 매개변수를 구분하고, 기본값·키워드 인수와 `return`을 사용해 계산 결과를 호출한 곳으로 돌려줄 수 있다.

### 왜 배우나요?

범위 판정 코드를 여러 곳에 복사하면 기준을 바꿀 때 모든 코드를 찾아 고쳐야 한다. 함수는 특정 일을 하나의 이름으로 묶어 여러 번 호출하게 한다. 좋은 함수는 필요한 값을 입력받고 결과를 반환한다.

### 정의와 호출은 다르다

```python
def is_in_range(value, lower=90.0, upper=100.0):
    return lower <= value <= upper

passed = is_in_range(94.2)
```

`def` 줄을 실행하면 Python은 함수의 이름과 본문을 **등록**한다. 본문은 아직 실행하지 않는다. `is_in_range(94.2)`처럼 괄호를 붙여 호출할 때 새 작업 공간이 생기고 본문이 실행된다.

| 용어 | 위 코드의 예 | 뜻 |
|---|---|---|
| 함수 이름 | `is_in_range` | 묶어 둔 일을 부르는 이름 |
| 매개변수 | `value`, `lower`, `upper` | 함수 안에서 입력을 받을 자리 |
| 인수 | `94.2` | 호출할 때 실제로 전달한 값 |
| 반환값 | `True` | 함수가 호출 위치로 돌려준 결과 |

### 인수가 연결되는 순서

```python
is_in_range(94.2)                  # value=94.2, lower=90.0, upper=100.0
is_in_range(94.2, 95.0)            # value=94.2, lower=95.0, upper=100.0
is_in_range(94.2, upper=94.0)      # value=94.2, lower=90.0, upper=94.0
```

위치 인수는 왼쪽부터 연결되고, 키워드 인수는 이름을 지정한다. 전달하지 않은 매개변수는 선언에 적힌 기본값을 사용한다.

### return과 print의 차이

```python
def show_average(values):
    print(sum(values) / len(values))

def get_average(values):
    return sum(values) / len(values)
```

`show_average`는 결과를 화면에 보여 주지만 호출한 코드가 그 값을 받아 계산할 수 없다. 반환문이 없으므로 실제 반환값은 `None`이다. `get_average`는 값을 반환하므로 `get_average(values) + 1`처럼 이어서 계산할 수 있다.

### 먼저 예상해 보기

위 세 `is_in_range` 호출의 반환값을 차례대로 적는다. 각 호출에서 하한과 상한이 무엇인지 먼저 적으면 실수가 줄어든다.

### 한 단계씩 따라가기

1. 호출 위치에서 인수의 현재 값을 계산한다.
2. 함수 전용 프레임을 만든다.
3. 인수를 매개변수에 연결하고 빠진 자리는 기본값으로 채운다.
4. 함수 본문을 실행한다.
5. `return`의 식을 계산한다.
6. 반환값을 호출 위치로 보내고 함수 프레임을 제거한다.
7. 호출 전체가 반환값으로 바뀌어 `passed`에 저장된다.

### 자주 하는 실수

- `is_in_range`는 함수 자체이고 `is_in_range(94.2)`는 호출 결과다.
- 인수 변수명과 매개변수 이름은 같을 필요가 없다. 위치 또는 키워드로 연결된다.
- `print()`를 했다고 반환한 것은 아니다.
- `return`을 실행하면 그 함수의 아래 코드는 실행하지 않고 즉시 호출 위치로 돌아간다.

### 직접 해보기

두 숫자를 받아 더 큰 값을 반환하는 `larger(a, b)` 함수를 작성한다. 화면에 출력만 하지 말고 다른 계산에 쓸 수 있게 반환한다. 두 값이 같은 경우도 시험한다.

## P13. Scope와 이름 탐색

### 이번 레슨이 끝나면

전역 변수와 지역 변수를 구분하고, 같은 이름이 여러 곳에 있을 때 어떤 값을 사용하는지 설명할 수 있다. 함수 종료 후 지역 변수가 사라지는 이유도 이해할 수 있다.

### 왜 배우나요?

여러 함수가 `total`, `status` 같은 이름을 사용해도 서로의 작업을 함부로 바꾸면 안 된다. Scope는 이름이 보이고 살아 있는 범위다. 함수 호출마다 독립된 지역 Scope가 생긴다.

### 같은 이름, 다른 변수

```python
threshold = 100.0

def check(value):
    threshold = 98.0
    return value <= threshold

result = check(99.0)
print(result)
print(threshold)
```

함수 안의 `threshold`와 바깥의 `threshold`는 이름만 같고 서로 다른 변수다. 함수 안에서 이름을 찾을 때 가장 가까운 지역 Scope를 먼저 보므로 98.0을 사용한다.

| 위치 | 선택되는 `threshold` | 결과 |
|---|---:|---|
| `check` 함수 안 | 98.0 | `99.0 <= 98.0`은 `False` |
| 함수 밖 | 100.0 | 출력은 `100.0` |

안쪽 이름이 바깥의 같은 이름을 잠시 가리는 것을 **shadowing**이라고 한다.

### 지역 변수의 수명

```python
def summarize(values):
    total = 0
    for value in values:
        total = total + value
    return total

print(summarize([94.0, 96.0]))
print(total)
```

함수가 끝나면 그 호출을 위한 프레임과 지역 변수 `total`, `value`가 사라진다. 따라서 마지막 줄의 `total`은 찾을 수 없어 `NameError`가 발생한다. 필요한 값은 이미 `return total`로 밖에 전달해야 한다.

### 이름을 찾는 기본 순서

입문 단계에서는 “현재 함수의 지역 Scope → 바깥 Scope → 전역 Scope → Python 내장 이름” 순서로 안쪽부터 찾는다고 이해한다. 전체 규칙은 Local, Enclosing, Global, Built-in의 머리글자를 따서 LEGB라고 부른다.

### 먼저 예상해 보기

위 `shadowing` 예제에서 출력되는 두 줄을 적고, 각각 어느 Scope의 값을 사용했는지 설명한다.

### 자주 하는 실수

- 함수 안에서 같은 이름에 할당하면 바깥 변수가 자동으로 바뀐다고 생각한다.
- 지역 변수를 함수 밖에서 계속 사용할 수 있다고 생각한다.
- 전역 변수를 많이 사용하면 편리하다고 생각한다. 실제로는 함수의 입력과 결과가 숨겨져 테스트와 재사용이 어려워진다.

### 직접 해보기

함수 안의 `threshold = 98.0`을 제거하고 `check(99.0)` 결과가 왜 바뀌는지 Scope 탐색 순서로 설명한다. 그다음 기준값을 매개변수로 받도록 고쳐 전역 변수 의존을 없앤다.

### 확인 문제

2. 같은 이름이 지역과 전역에 모두 있으면 함수 안에서 어느 것을 먼저 찾는가?
3. 지역 계산 결과를 함수 밖에서 사용하려면 어떻게 해야 하는가?

<details>
<summary>정답과 해설</summary>

2. 지역 변수를 먼저 찾는다.
3. `return`으로 값을 돌려주고 호출한 쪽에서 변수에 저장한다.
4. 예상 출력은 `False`, `100.0`이다.

</details>

## P14. 반복 처리 패턴 — 변환, 필터, 집계

### 이번 레슨이 끝나면

컬렉션 반복 코드를 변환, 필터, 집계 중 하나로 분류하고 각 패턴에 맞는 결과 변수를 만들 수 있다.

### 왜 배우나요?

데이터 처리 코드는 달라 보여도 대부분 세 가지 질문 중 하나에 답한다.

- **변환:** 각 값을 다른 값으로 바꾸려는가?
- **필터:** 조건에 맞는 값만 남기려는가?
- **집계:** 여러 값을 하나의 합계·개수·평균으로 모으려는가?

문제의 종류를 먼저 알면 반복문 안에서 무엇을 해야 할지 정하기 쉽다.

### 공통 구조

결과를 담을 그릇은 반복문 **앞에서 한 번** 만든다. 반복문 안에서 만들면 회차마다 빈 그릇으로 초기화되어 이전 결과가 사라진다.

#### 변환

```python
adjusted = []
for value in measurements:
    adjusted.append(value + 1.0)
```

입력 원소마다 결과 원소가 하나 생긴다. 보통 입력과 결과 길이가 같다.

#### 필터

```python
passed = []
for value in measurements:
    if 90.0 <= value <= 100.0:
        passed.append(value)
```

조건을 통과한 원본 값만 결과에 들어간다. 결과 길이는 입력보다 작거나 같다.

#### 집계

```python
total = 0
count = 0
for value in measurements:
    total = total + value
    count = count + 1
```

회차마다 이전 상태를 갱신해 마지막에 하나의 요약값을 만든다.

### 먼저 예상해 보기

입력 `[94.2, 101.3, 96.0, 88.7]`에서 다음을 구한다.

1. 모든 값에 1을 더한 변환 결과
2. 90 이상 100 이하인 필터 결과
3. 전체 합계와 개수

### 실행표로 집계 확인하기

| 회차 | 현재 값 | 이전 `total` | 새 `total` | 새 `count` |
|---:|---:|---:|---:|---:|
| 1 | 94.2 | 0 | 94.2 | 1 |
| 2 | 101.3 | 94.2 | 195.5 | 2 |
| 3 | 96.0 | 195.5 | 291.5 | 3 |

평균은 반복이 끝난 뒤 `total / count`로 계산한다. 빈 List에서는 `count`가 0이므로 먼저 방어해야 한다.

### 자주 하는 실수

```python
for value in measurements:
    passed = []             # 매 회차 다시 비워짐
    if value <= 100:
        passed.append(value)
```

`passed = []`는 반복문 앞으로 옮긴다.

```python
total = value              # 이전 합계를 버림
total = total + value      # 이전 합계에 현재 값을 더함
```

집계는 직전 상태를 사용해야 한다.

### 직접 해보기

입력에서 `None`을 제외하고 나머지 숫자의 합계와 개수를 구한다. 평균을 계산하기 전에 유효값이 하나도 없는 경우도 처리한다.

### 확인 문제

1. 결과 List의 길이가 입력과 항상 같다면 어떤 패턴일 가능성이 큰가?
2. 조건을 통과한 값만 모으면 어떤 패턴인가?
3. 결과 변수를 반복문 앞에 만드는 이유는 무엇인가?

<details>
<summary>정답과 해설</summary>

1. 변환이다.
2. 필터다.
3. 회차마다 이전 결과를 유지하고 이어서 갱신하기 위해서다.
4. 예상 결과는 `[95.2, 102.3, 97.0, 89.7]`, `[94.2, 96.0]`, 합계 380.2와 개수 4다.

</details>

## P15. Comprehension

### 이번 레슨이 끝나면

단순한 변환과 필터 반복문을 List 또는 Dictionary Comprehension으로 표현하고, 한 줄 코드를 실제 실행 순서대로 읽을 수 있다.

### 왜 배우나요?

“각 값을 하나씩 꺼내 조건을 확인하고 결과 List에 추가한다”는 구조가 분명할 때 Python은 결과를 만드는 목적을 한 줄에 표현할 수 있다. 단, 짧다고 항상 쉬운 코드는 아니다. 조건과 변환이 한눈에 들어올 때만 사용한다.

### 쓰는 순서와 실행 순서

```python
passed = [value for value in measurements if 90.0 <= value <= 100.0]
```

글자는 앞에서부터 쓰지만 실행은 다음 순서로 이해한다.

1. `for value in measurements`: 원소 하나를 꺼낸다.
2. `if ...`: 조건을 검사한다.
3. 맨 앞 `value`: 통과한 값을 결과에 넣는다.
4. 다음 원소에서 반복한다.

다음 일반 반복문과 같은 결과다.

```python
passed = []
for value in measurements:
    if 90.0 <= value <= 100.0:
        passed.append(value)
```

### 변환과 Dictionary 만들기

```python
labels = [f"M{index}" for index in range(3)]
squared = {value: value ** 2 for value in range(3)}
```

첫 코드는 `['M0', 'M1', 'M2']`, 두 번째 코드는 `{0: 0, 1: 1, 2: 4}`를 새로 만든다.

### 먼저 예상해 보기

```python
values = [1, 2, 3, 4]
result = [value * 10 for value in values if value % 2 == 0]
```

각 원소가 조건을 통과하는지, 통과한 뒤 어떤 값으로 변환되는지 표로 적는다.

### 자주 하는 실수

- 맨 앞 표현식이 먼저 한 번 실행된다고 생각한다. 실제로는 각 원소가 조건을 통과할 때 실행된다.
- 원본 List를 직접 바꾼다고 생각한다. Comprehension은 새 컬렉션을 만든다.
- 여러 중첩 조건과 부수 효과를 한 줄에 넣는다. 한눈에 설명하기 어렵다면 일반 반복문이 낫다.

### 직접 해보기

measurement 중 100 이하인 값만 골라 `"OK:94.2"` 형태의 문자열로 변환한다. 먼저 일반 반복문으로 쓴 다음 Comprehension으로 바꾼다.

### 확인 문제

1. `[x + 1 for x in [1, 2, 3]]`의 결과는 무엇인가?
2. Comprehension의 `if`는 값을 바꾸는가, 포함 여부를 정하는가?
3. 한 줄이 너무 복잡해 실행 순서를 설명할 수 없다면 어떤 형태가 더 좋은가?

<details>
<summary>정답과 해설</summary>

1. `[2, 3, 4]`다.
2. 포함 여부를 정한다. 맨 앞 표현식이 값을 변환한다.
3. 여러 줄의 일반 `for` 반복문이 더 읽기 좋다.
4. 예상 문제 결과는 `[20, 40]`이다.

</details>

## P16. enumerate, zip, Unpacking

### 이번 레슨이 끝나면

값과 순번을 함께 순회하고, 두 컬렉션의 같은 위치끼리 묶을 수 있다. 묶여 나온 Tuple을 여러 변수로 분해할 수 있다.

### 왜 배우나요?

List 원소와 표시용 순번이 함께 필요하다고 해서 `range(len(...))`를 항상 사용할 필요는 없다. 또 Wafer ID와 measurement가 별도 List에 있다면 같은 위치끼리 안전하게 꺼내야 한다.

### enumerate

```python
wafers = ["W01", "W02", "W03"]

for index, wafer_id in enumerate(wafers, start=1):
    print(index, wafer_id)
```

`enumerate`는 원소마다 `(순번, 원소)` Tuple을 만든다. 첫 회차에는 `(1, "W01")`이 나오고 Unpacking으로 `index = 1`, `wafer_id = "W01"`이 된다. `start=1`은 표시 순번을 1에서 시작할 뿐 원본 List 인덱스를 바꾸지 않는다.

### zip

```python
wafers = ["W01", "W02", "W03"]
values = [94.2, 101.3]

for wafer_id, value in zip(wafers, values):
    print(wafer_id, value)
```

`zip`은 `(W01, 94.2)`, `(W02, 101.3)`을 만든 뒤 끝난다. 짧은 `values`에 더 이상 원소가 없으므로 `W03`은 조합되지 않는다. 데이터 누락을 조용히 지나칠 수 있으므로 길이가 같아야 하는 데이터라면 먼저 검증한다.

### Unpacking

```python
pair = ("W01", 94.2)
wafer_id, value = pair
```

오른쪽에 원소 두 개가 있으므로 왼쪽에도 변수 두 개가 필요하다. 개수가 맞지 않으면 `ValueError`가 발생한다.

### 먼저 예상해 보기

```python
names = ["A", "B", "C"]
values = [10, 20]
pairs = list(zip(names, values))
```

`pairs`의 길이와 전체 내용을 적는다.

### 자주 하는 실수

- `enumerate`가 원본 값을 인덱스로 바꾼다고 생각한다. 실제로는 `(순번, 원소)`를 함께 준다.
- `zip`이 긴 쪽의 남은 값도 `None`과 묶는다고 생각한다. 기본 `zip`은 짧은 쪽에서 끝난다.
- `a, b = (1, 2, 3)`처럼 변수와 원소 개수를 다르게 둔다.

### 직접 해보기

Wafer ID 세 개와 measurement 두 개를 `zip`하기 전에 길이를 검사한다. 다르면 `"데이터 개수 불일치"`를 출력하고, 같을 때만 조합을 출력한다.

### 확인 문제

1. `enumerate(["A", "B"], start=1)`의 첫 Tuple은 무엇인가?
2. 길이 4와 길이 2인 List를 `zip`하면 조합은 몇 개인가?
3. `x, y = [10, 20]`에서 `x`와 `y`는 각각 무엇인가?

<details>
<summary>정답과 해설</summary>

1. `(1, "A")`다.
2. 짧은 쪽 길이에 맞춰 2개다.
3. `x = 10`, `y = 20`이다.
4. 예상 문제 결과는 `[('A', 10), ('B', 20)]`, 길이는 2다.

</details>

## P17. 정렬, key, lambda

### 이번 레슨이 끝나면

`sorted()`와 `.sort()`의 원본 변경·반환값 차이를 설명할 수 있다. `key` 함수로 Dictionary 레코드의 정렬 기준을 선택할 수 있다.

### 왜 배우나요?

단순 숫자는 크기대로 정렬하면 되지만 Wafer 레코드는 ID, measurement, 상태 중 무엇을 기준으로 볼지 정해야 한다. 또한 분석 중에는 원본 순서를 보존해야 할 수도 있다.

### sorted와 sort 비교

```python
values = [96.0, 94.2, 101.3]
new_list = sorted(values)
```

`sorted()`는 새 List `[94.2, 96.0, 101.3]`을 반환하고 원본 `values`는 그대로 둔다.

```python
result = values.sort()
```

`.sort()`는 `values` 자체를 정렬하고 반환값은 `None`이다. 따라서 이 코드 뒤에는 `values == [94.2, 96.0, 101.3]`, `result is None`이다.

### 레코드의 정렬 기준

```python
records = [
    {"wafer": "W01", "measurement": 94.2},
    {"wafer": "W02", "measurement": 101.3},
    {"wafer": "W03", "measurement": 96.0},
]

ordered = sorted(
    records,
    key=lambda item: item["measurement"],
    reverse=True,
)
```

`key`에 준 함수는 원소마다 한 번씩 호출되어 비교 기준값을 꺼낸다. 첫 레코드에서는 94.2, 두 번째에서는 101.3, 세 번째에서는 96.0을 얻는다. `reverse=True`이므로 큰 값부터 정렬한다.

### 먼저 예상해 보기

위 `ordered`에서 첫 번째와 마지막 Wafer ID를 적는다. 그다음 `reverse=False`로 바꾸면 어떻게 되는지 예상한다.

### lambda는 짧은 함수다

```python
lambda item: item["measurement"]
```

이 표현은 원소 하나를 `item`으로 받아 measurement를 반환하는 이름 없는 짧은 함수다. 복잡한 계산이나 여러 단계가 필요하면 `def`로 이름 있는 함수를 만드는 편이 읽기 좋다.

### 자주 하는 실수

```python
ordered = values.sort()  # ordered에는 None이 저장됨
```

원본 변경이 필요하면 `values.sort()`만 호출하고 이후 `values`를 사용한다. 새 List가 필요하면 `ordered = sorted(values)`를 사용한다.

문자열 숫자 `"10"`, `"2"`는 숫자가 아니라 글자 순서로 정렬되어 `"10"`이 먼저 올 수 있다. 숫자 순서가 필요하면 `key=float`처럼 변환 기준을 준다.

### 직접 해보기

같은 레코드를 ① Wafer ID 오름차순, ② measurement 내림차순으로 각각 정렬한다. 두 결과에서 원본 `records`가 바뀌지 않았는지 확인한다.

### 확인 문제

1. 새 List를 만들고 원본을 보존하는 함수는 무엇인가?
2. `.sort()`의 반환값은 무엇인가?
3. `key` 함수는 각 원소에서 무엇을 반환해야 하는가?

<details>
<summary>정답과 해설</summary>

1. `sorted()`다.
2. `None`이다. 원본 List 자체가 바뀐다.
3. 원소들을 비교할 때 사용할 기준값을 반환한다.
4. 예상 문제의 첫 Wafer는 W02, 마지막은 W01이다. 오름차순이면 반대 방향으로 W01이 첫 번째가 된다.

</details>
