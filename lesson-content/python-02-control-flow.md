## P08. 조건문

### 이번 레슨이 끝나면

`if`, `elif`, `else`로 여러 가능성 중 하나의 실행 경로를 고를 수 있다. 조건의 순서와 경계값에 따라 결과가 달라지는 이유도 설명할 수 있다.

### 왜 배우나요?

모든 데이터에 같은 일을 할 수는 없다. measurement가 너무 낮으면 `LOW`, 범위 안이면 `PASS`, 너무 높으면 `HIGH`처럼 값에 따라 다른 처리가 필요하다. 조건문은 컴퓨터에게 “이 질문이 참이면 이쪽, 아니면 다른 쪽으로 가라”고 알려 준다.

### 문법을 읽는 법

```python
measurement = 104.3

if measurement < 90.0:
    status = "LOW"
elif measurement <= 100.0:
    status = "PASS"
else:
    status = "HIGH"
```

- `if`부터 위에서 아래로 조건을 검사한다.
- 조건 뒤의 `:`는 코드 블록이 시작된다는 표시다.
- 네 칸 들여쓴 줄만 해당 조건의 블록에 속한다.
- 참인 조건을 처음 만나면 그 블록만 실행하고 나머지 `elif`와 `else`는 건너뛴다.
- `else`에는 조건이 없다. 앞의 조건이 모두 거짓일 때 실행된다.

### 값의 범위를 먼저 그리기

```text
measurement < 90.0       → LOW
90.0 <= measurement <= 100.0 → PASS
measurement > 100.0      → HIGH
```

두 번째 코드가 `measurement <= 100.0`만 검사해도 되는 이유는 그 지점에 도착했다면 첫 조건 `measurement < 90.0`이 이미 거짓이기 때문이다. 즉 90.0 이상이라는 사실을 알고 있다.

### 먼저 예상해 보기

다음 값을 넣었을 때 실행되는 조건과 `status`를 채운다.

| 값 | 첫 조건 `< 90` | 두 번째 조건 `<= 100` | 결과 |
|---:|---|---|---|
| 88.5 | ? | 검사함/안 함 | ? |
| 90.0 | ? | ? | ? |
| 100.0 | ? | ? | ? |
| 104.3 | ? | ? | ? |

### 한 단계씩 따라가기

`measurement = 94.2`일 때 실행은 다음과 같다.

1. `94.2 < 90.0`을 계산한다. 결과는 `False`라서 `LOW` 블록을 건너뛴다.
2. `94.2 <= 100.0`을 계산한다. 결과는 `True`다.
3. `status = "PASS"`를 실행한다.
4. 이미 경로를 골랐으므로 `else`는 실행하지 않는다.
5. 조건문 다음 줄로 이동한다.

### 독립된 if와 if/elif/else

```python
if value >= 90:
    print("90 이상")
if value <= 100:
    print("100 이하")
```

두 `if`는 서로 독립적이라 둘 다 참이면 두 줄 모두 출력된다. 반면 `if/elif/else` 묶음에서는 최대 한 블록만 실행된다. 여러 조건이 동시에 실행되어야 하는지, 하나만 골라야 하는지에 따라 구조를 선택한다.

### 자주 하는 실수

```python
if measurement < 90:
    status = "LOW"
elif measurement < 100:  # 100.0은 포함되지 않는다.
    status = "PASS"
```

100.0도 PASS라면 `<`가 아니라 `<=`가 필요하다.

```python
if passed:
status = "PASS"          # IndentationError
```

블록 안의 코드는 반드시 들여쓴다. 들여쓰기는 꾸밈이 아니라 코드 구조다.

### 직접 해보기

다음 규칙으로 `status`를 정한다.

- 0보다 작으면 `"INVALID"`
- 0 이상 90 미만이면 `"LOW"`
- 90 이상 100 이하면 `"PASS"`
- 100보다 크면 `"HIGH"`

경계값 `-0.1`, `0`, `89.9`, `90`, `100`, `100.1`로 빠지거나 겹치는 구간이 없는지 확인한다.

### 확인 문제

1. `if/elif/else` 묶음에서 최대 몇 개의 블록이 실행되는가?
2. 첫 조건이 참이면 아래 `elif` 조건도 계산하는가?
3. 10 이상 20 이하를 표현하는 조건을 작성해 보자.

<details>
<summary>정답과 해설</summary>

1. 최대 한 개다.
2. 계산하지 않는다. 처음 참인 경로를 실행한 뒤 묶음을 빠져나간다.
3. `10 <= value <= 20`으로 쓸 수 있다.
4. 예상표 결과는 차례로 `LOW`, `PASS`, `PASS`, `HIGH`다. 88.5에서는 두 번째 조건을 검사하지 않고, 나머지 세 값에서는 검사한다.

</details>

## P09. for, range, 기본 반복

### 이번 레슨이 끝나면

List의 값을 하나씩 꺼내 반복하고 `range()`로 원하는 숫자 흐름을 만들 수 있다. 반복 횟수와 반복 변수의 값을 실행 전에 계산할 수 있다.

### 왜 배우나요?

Wafer가 100장인데 같은 검사 코드를 100번 복사하면 수정도 어렵고 실수도 늘어난다. 반복문은 “이 값들을 하나씩 꺼내 같은 본문을 실행하라”고 표현한다.

### List의 값을 직접 순회하기

```python
wafers = ["W01", "W02", "W03"]

for wafer_id in wafers:
    print("검사:", wafer_id)
```

`wafer_id`는 회차마다 List의 다음 **원소 자체**를 받는다.

| 회차 | `wafer_id` | 출력 |
|---:|---|---|
| 1 | `"W01"` | `검사: W01` |
| 2 | `"W02"` | `검사: W02` |
| 3 | `"W03"` | `검사: W03` |

더 꺼낼 원소가 없으면 반복을 끝내고 들여쓰기가 끝난 다음 줄로 이동한다.

### range 이해하기

```python
for number in range(1, 6, 2):
    print(number)
```

`range(시작, 끝, 간격)`은 시작을 포함하고 끝은 포함하지 않는다. 위 코드는 1에서 시작해 2씩 증가하므로 `1, 3, 5`를 만든다. 다음 값 7은 끝 6을 이미 넘으므로 사용하지 않는다.

| 코드 | 만들어지는 값 |
|---|---|
| `range(5)` | `0, 1, 2, 3, 4` |
| `range(1, 5)` | `1, 2, 3, 4` |
| `range(1, 6, 2)` | `1, 3, 5` |
| `range(5, 0, -2)` | `5, 3, 1` |

### 누적값 따라가기

```python
total = 0

for index in range(0, 5):
    total = total + index
```

| 회차 | `index` | 계산 | 새 `total` |
|---:|---:|---|---:|
| 시작 | 없음 | 초깃값 | 0 |
| 1 | 0 | `0 + 0` | 0 |
| 2 | 1 | `0 + 1` | 1 |
| 3 | 2 | `1 + 2` | 3 |
| 4 | 3 | `3 + 3` | 6 |
| 5 | 4 | `6 + 4` | 10 |

### 먼저 예상해 보기

`range(2, 9, 3)`이 만드는 값, 반복 횟수, 마지막 반복 변수 값을 적는다.

### 자주 하는 실수

- `range(0, 5)`에 5가 포함된다고 생각한다. 끝은 제외되므로 마지막은 4다.
- `for wafer_id in wafers`에서 `wafer_id`가 0, 1, 2라고 생각한다. 이 문법은 원소 자체를 준다.
- 반복할 List를 순회 중에 추가·삭제하면 어느 원소가 다음인지 헷갈릴 수 있다. 입문 단계에서는 원본 길이를 바꾸지 않는다.
- Python의 반복 변수는 반복 종료 후에도 마지막 값을 가리킨다. 다만 그 값에 의존하는 코드는 읽기 어려우므로 필요한 결과는 별도 변수에 저장한다.

### 직접 해보기

`range()`를 사용해 2, 4, 6, 8을 차례로 출력한다. 시작, 끝, 간격을 직접 정하고 끝값이 왜 그 숫자여야 하는지 설명한다.

### 확인 문제

1. `range(3)`이 만드는 값은 무엇인가?
2. List를 직접 순회하면 반복 변수에 인덱스와 원소 중 무엇이 들어가는가?
3. 10, 7, 4, 1을 만드는 `range()`를 작성해 보자.

<details>
<summary>정답과 해설</summary>

1. `0, 1, 2`다.
2. 원소 자체가 들어간다.
3. `range(10, 0, -3)`으로 쓸 수 있다.
4. 예상 문제의 값은 `2, 5, 8`, 반복은 3회, 마지막 값은 8이다.
5. 직접 해보기는 `range(2, 10, 2)`가 한 답이다. 끝 10은 포함되지 않는다.

</details>

## P10. while, break, continue

### 이번 레슨이 끝나면

조건이 참인 동안 `while`로 반복하고, `continue`로 현재 회차의 나머지를 건너뛰거나 `break`로 반복 전체를 끝낼 수 있다. 무한 반복이 생기는 이유도 찾을 수 있다.

### 왜 배우나요?

연결이 몇 번째 시도에 성공할지는 미리 알 수 없다. 이런 경우 “최대 세 번이면서 아직 연결되지 않은 동안”처럼 **상태를 조건으로** 반복한다.

### while의 실행 순서

```python
attempt = 0
connected = False

while attempt < 3 and not connected:
    attempt = attempt + 1
    connected = attempt == 2
```

1. `attempt < 3 and not connected`를 계산한다.
2. 참이면 들여쓴 본문을 실행한다.
3. 본문이 `attempt`나 `connected` 상태를 바꾼다.
4. 다시 조건 줄로 돌아간다.
5. 조건이 거짓이면 본문에 들어가지 않고 반복 다음 줄로 간다.

| 조건 검사 시점 | `attempt` | `connected` | 결과 |
|---:|---:|---|---|
| 1 | 0 | `False` | 참, 1회차 실행 |
| 2 | 1 | `False` | 참, 2회차 실행 |
| 3 | 2 | `True` | 거짓, 종료 |

### continue와 break

```python
measurements = [94.2, None, 101.3, 96.0]
index = 0

while index < len(measurements):
    value = measurements[index]
    index = index + 1
    if value is None:
        continue
    if value > 100.0:
        break
    print(value)
```

- `continue`는 현재 회차의 아래 코드를 건너뛰고 조건 검사로 돌아간다. 반복 자체는 계속된다.
- `break`는 조건을 다시 검사하지 않고 가장 가까운 반복문 전체를 끝낸다.

이 예제는 94.2를 출력하고, `None`은 건너뛰며, 101.3에서 반복을 끝낸다. 따라서 뒤의 96.0은 읽지 않는다.

### 먼저 예상해 보기

위 코드에서 최종 `index`는 얼마이고 몇 개의 숫자가 출력되는가? `continue`와 `break` 직전에 이미 `index`가 증가했다는 점을 확인한다.

### 무한 반복이 생기는 이유

```python
count = 0
while count < 3:
    print(count)
```

본문이 `count`를 바꾸지 않으므로 조건 `count < 3`은 계속 참이다. `while`을 작성할 때는 다음 세 질문에 답해야 한다.

1. 반복을 시작하기 전 상태는 무엇인가?
2. 어떤 조건에서 계속하는가?
3. 본문의 어느 줄이 그 조건을 언젠가 거짓으로 만드는가?

### 자주 하는 실수

`continue`보다 아래에 `index += 1`을 두면 누락값에서 증가하지 않고 같은 원소를 영원히 다시 볼 수 있다. 상태 갱신은 건너뛰기 전에 실행하거나, 코드 구조상 반드시 실행되도록 설계한다.

`break`는 `if`만 끝내는 문법이 아니다. 가장 가까운 `for` 또는 `while` 전체를 끝낸다.

### 직접 해보기

첫 음수를 만나면 멈추고 `None`은 건너뛰면서, 그전까지의 유효 숫자 개수를 세는 코드를 작성한다. 입력 `[3, None, 5, -1, 8]`에서 최종 개수와 마지막으로 읽은 값을 예상한다.

### 확인 문제

1. `continue`와 `break`의 차이를 한 문장씩 설명해 보자.
2. `while True:`도 끝날 수 있는가?
3. 반복 조건에 쓰는 값이 본문에서 전혀 바뀌지 않으면 어떤 위험이 있는가?

<details>
<summary>정답과 해설</summary>

1. `continue`는 현재 회차의 남은 부분만 건너뛰고 다음 조건 검사로 가며, `break`는 반복 전체를 끝낸다.
2. 본문에서 조건에 따라 `break`를 실행하면 끝날 수 있다. `break`가 없다면 무한 반복이다.
3. 조건이 계속 참으로 남아 무한 반복이 될 수 있다.
4. 예상 문제의 최종 `index`는 3이고 출력된 숫자는 94.2 한 개다.
5. 직접 해보기의 유효 개수는 2이고 마지막으로 읽은 값은 -1이다. 8은 읽지 않는다.

</details>

## P11. 중첩 반복문

### 이번 레슨이 끝나면

바깥 반복 한 회마다 안쪽 반복이 처음부터 끝까지 실행되는 순서를 설명할 수 있다. 두 반복의 전체 조합 수와 다음 조합도 계산할 수 있다.

### 왜 배우나요?

Lot 3개와 Wafer 위치 4개를 모두 조합하려면 3×4개의 경우를 확인해야 한다. 바깥 반복은 Lot을 고정하고, 안쪽 반복은 그 Lot에서 모든 Wafer 위치를 차례로 순회한다.

### 가장 작은 2×3 예제

```python
for i in range(2):
    for k in range(3):
        print(i, k)
```

실행 순서는 다음과 같다.

```text
(0, 0) → (0, 1) → (0, 2)
                         ↓ k가 끝남
(1, 0) → (1, 1) → (1, 2)
```

`i = 0`인 동안 `k`가 0, 1, 2를 모두 돈다. 그제야 `i`가 1이 되고 `k`는 새 안쪽 반복을 시작하므로 다시 0부터 시작한다.

### 전체 실행 횟수

바깥 반복이 2회, 안쪽 반복이 바깥 회차마다 3회이므로 본문은 `2 × 3 = 6`회 실행된다. 9×9라면 81회다. 반복이 세 겹이면 각 반복 횟수를 모두 곱한다.

### 함수 호출까지 따라가기

```python
def mul(a, b):
    return a * b

for i in range(3):
    for k in range(3):
        result = mul(i, k)
```

조합 `(2, 1)`에서는 `mul(i, k)`가 현재 값으로 `mul(2, 1)`이 된다. 새 함수 프레임에서 `a = 2`, `b = 1`이 연결되고 2를 반환해 `result`에 저장한다. 다음 조합 `(2, 2)`에서는 같은 과정을 새 값으로 반복한다.

### 먼저 예상해 보기

1. 3×3 반복에서 `(0, 2)` 다음 조합은 무엇인가?
2. `(1, 2)` 다음 조합은 무엇인가?
3. 4×5 반복의 가장 안쪽 본문은 총 몇 번 실행되는가?

### 한 단계씩 관찰할 지점

- 안쪽 반복이 끝난 순간 `k`가 어떻게 되는가?
- 바깥 변수 `i`는 안쪽 반복 중에 바뀌는가?
- 새 바깥 회차가 시작되면 `k`는 어디서 다시 시작하는가?
- `mul`은 조합마다 새로 호출되는가?

9×9 전체를 한 단계씩 누를 필요는 없다. 처음 세 조합, `k=8`에서 다음 `i`로 넘어가는 전환, 마지막 조합을 대표로 관찰한다.

### 자주 하는 실수

- `i`와 `k`가 동시에 한 칸씩 증가한다고 생각한다. 실제로는 안쪽 `k`가 먼저 전체를 돈다.
- 안쪽 반복이 한 번 끝난 뒤 다시 시작하지 않는다고 생각한다. 바깥 회차마다 안쪽 반복문을 새로 실행한다.
- 출력이나 함수 호출의 들여쓰기를 안쪽 반복 밖으로 빼면 바깥 회차당 한 번만 실행된다.

```python
for i in range(2):
    for k in range(3):
        pass
    print(i, k)  # 안쪽 반복이 끝난 뒤, 바깥 회차마다 한 번
```
